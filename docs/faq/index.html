What is the AI UX Discovery-to-Prototype Pipeline?

It is a reusable, Markdown-defined AI design process that takes a BRD and supporting UX inputs through Research → Ideation → Design → Validation. A Python and Streamlit runtime demonstrates the same governed workflow, while human gates control progression.

Does the pipeline accept only a BRD?

No. The BRD is the primary starting point, but the input folder can also contain relevant supporting material such as research notes, survey summaries, analytics, support tickets, stakeholder notes, existing flows, design-system guidance, and constraints. The quality of the outputs depends on the quality and traceability of those inputs.

What are the four phases?
  1. Discover: analyze evidence, challenge the BRD, synthesize personas, pain points, and research gaps.
  2. Define & Ideate: frame the problem, map the journey, identify opportunities, and select a concept.
  3. Design & Prototype: define flows, screens, interaction states, and generate a workable prototype.
  4. Validate: perform evidence, heuristic, accessibility, and synthetic usability audits before final human approval.
Which agents are involved, and what does each one own?
  • UX Research Agent: source analysis, personas, pain points, and research gaps.
  • Requirements Challenge Agent: pre-design BRD challenge and risk analysis.
  • UX Definition & Ideation Agent: problem framing, journey mapping, opportunities, and concept selection.
  • Experience Design Agent: user flow, information architecture, screen and state specifications, and prototype generation.
  • UX Validation & Audit Agent: validation evidence, accessibility and heuristic review, and final audit reporting.
What do Advocate, Cynic, and Debate Synthesis actually do?

They are three reusable skills invoked by the Requirements Challenge Agent:

Advocate

Builds the strongest evidence-based interpretation of the BRD—its supported goals, needs, happy paths, constraints, and strengths.

Cynic

Stress-tests ambiguity, edge cases, accessibility, user trust, failure states, and missing requirements without turning suspicion into fact.

Debate Synthesis

Reconciles both views into a concise, traceable risk review with classifications, confidence, evidence locators, questions, and actions.

Why use skills instead of creating more agents?

An agent owns a responsibility and handoff; a skill is a reusable capability it invokes. Keeping Advocate, Cynic, and Debate Synthesis as skills gives the Requirements Challenge Agent one accountable owner while avoiding overlapping or competing agents.

What is the difference between Demo Mode and Live AI Mode?

Demo Mode uses predefined synthetic inputs and deterministic example outputs. It works without an API key and consumes no model quota. Live AI Mode sends the declared phase inputs and instructions to Gemini and requires both the configured Gemini API key and the Live AI access password.

Why is Live AI Mode password-protected?

The application is public, while model calls can consume the owner's API quota. The password is a shared-demo safeguard against casual unauthorized use; it is not a full user-account or enterprise authentication system.

How can I test the application safely?
  1. Open the Streamlit runner.
  2. Keep Demo Mode selected.
  3. Review the predefined synthetic inputs.
  4. Run Phase 1 and inspect the generated artifacts.
  5. Use the D1 decision controls; only APPROVE unlocks Phase 2.
  6. Continue through D4, reviewing the outputs at every gate.
  7. Open the final prototype and downloadable artifacts.
Can the entire flow run without waiting for approval?

No—not in the governed workflow. Each phase deliberately stops at D1, D2, D3, or D4. Only an explicit human APPROVE advances the workflow. This is a core safety and quality-control feature, not a technical limitation.

Is this a Python-only project?

No. The workflow is defined in Markdown and can guide a compatible agentic environment that can read the files, follow ordered instructions, create declared artifacts, and pause for human decisions. The Python runtime validates and demonstrates those contracts; Streamlit provides the public UI. The static documentation and prototype use HTML, CSS, and JavaScript.

What do APPROVE, REVISE, and REJECT mean?
  • APPROVE: unlock the next phase; D4 approval completes the workflow.
  • REVISE: rerun only the affected work and its dependent outputs, then return to the gate.
  • REJECT: stop the workflow and record the decision.

Agents cannot approve their own work.

How does the pipeline prevent invented research?

Findings must distinguish facts and BRD statements from inferences, assumptions, and risk hypotheses. Substantive challenge findings include confidence and a source locator where available. Risk hypotheses cannot automatically become persona attributes, pain points, confirmed requirements, or research findings.

Does the accessibility audit certify WCAG compliance?

No. The pipeline identifies accessibility risks and items requiring validation. It does not claim formal WCAG conformance unless sufficient evidence and appropriate testing support that conclusion.

Is synthetic usability validation the same as real-user research?

No. Synthetic validation can expose plausible issues and help prepare research questions, but it is not evidence from real participants. Demo inputs and related findings remain explicitly labelled SYNTHETIC DEMO DATA.

What does the pipeline produce?

Outputs include a BRD risk review, persona, pain points, research gaps, problem definition, journey map, opportunities, selected concept, user flow, screen specification, interaction states, prototype specification, a runnable prototype, validation findings, an audit report, and recorded human review decisions.

When can the prototype be called verified and workable?

Only after Phase 4 validation and explicit human D4 APPROVE. Even then, the claim is bounded by the documented evidence and synthetic demo scope; it does not imply production readiness or real-user validation.
