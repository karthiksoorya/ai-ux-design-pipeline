# Interaction State Skill

## Name & Description
Specifies important happy-path and non-happy-path interaction states for the approved screens and flow.

## Role
Support the Experience Design Agent in defining prototype behavior before generation.

## Input
outputs/phase-03/user-flow.md and outputs/phase-03/screen-spec.md plus approved requirements and concept.

## Output
outputs/phase-03/interaction-states.md

## Rules & Guardrails
- Cover loading, empty, error, validation error, cancellation, timeout, unavailable service, permission, recovery, and exit states when relevant.
- Mark a state NOT APPLICABLE with rationale rather than silently omitting it.
- Do not invent backend behavior, policy, or recovery capability.
